# Architecture decisions

Compare at least two viable options against explicit requirements. Use an ordinal rubric with anchored reasons, not arbitrary precise-looking scores. Compare six pillars, TCO, latency, team cognitive load and lock-in; mark unknown monetary or latency inputs.

Compute weighted totals consistently with the disclosed weights; explain constraints that override the score. Do not always select microservices for enterprise or monoliths for MVPs. Deployment complexity, team ownership, consistency and failure isolation decide suitability.

Each ADR includes context, considered options, chosen option, evidence, consequences, assumptions and reconsideration triggers. Keep migration implications separate from the observed model. The runtime default matrix is illustrative and must be replaced by a grounded agent assessment for substantive design recommendations.
